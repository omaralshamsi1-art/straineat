# StrainEat — حاسبة القيمة الغذائية بالصورة

يصوّر المستخدم وجبته، فيتعرف عليها وكيل ذكي (Claude) ويحسب سعراتها وقيمتها الغذائية، ثم يقارنها بالحرق اليومي القادم من Apple Health أو WHOOP أو أي جهاز آخر.

**📋 قائمة المميزات الكاملة: [FEATURES.md](FEATURES.md)**

## كيف يعمل الوكيل

ترتيب المصادر (يُستخدم الأعلى المتاح):

| الأولوية | المصدر | متى |
|---|---|---|
| 1 | **وجباتك السابقة** (`known_meal`) | الوجبات التي أكّدها المستخدم سابقاً، شاملة تعديلاته |
| 2 | **القيمة المعلنة من المطعم** (`restaurant_published`) | يبحث في الويب: موقع المطعم، ملفات القيمة الغذائية، تطبيقات التوصيل (طلبات، ديليفرو، كريم، نون) ويفضّل منيو الإمارات |
| 3 | **قاعدة بيانات غذائية** (`database`) | للأصناف العامة (USDA وغيرها) |
| 4 | **تقدير من الصورة** (`estimate`) | يقدّر الأوزان من الصورة ويحسب الزيوت والسمن المخفية، ويعرض افتراضاته ليعدّلها المستخدم |

**التعلّم (الخبرة):** عند تأكيد وجبة تُحفظ قيمها النهائية كـ«وجبة معروفة» للمستخدم، فإذا صوّرها مرة أخرى يستخدم الوكيل أرقامه هو. القيم المعلنة الموثقة بمصدر وغير المعدّلة تُحفظ عالمياً لتفيد كل المستخدمين.

**ضمانات الدقة على الخادم:**
- يُعاد حساب المجموع من المكونات دائماً، ولا يُعتمد على رقم الإجمالي من النموذج.
- فحص أتواتر (4/4/9): إذا اختلفت السعرات عن الماكروز بأكثر من 20% يظهر تنبيه.
- تُحذف الروابط التي لم تأتِ فعلاً من نتائج البحث. وإذا ادّعى النموذج «قيمة معلنة» بلا مصدر موثّق تُخفَّض الثقة إلى 60% كحد أقصى مع تنبيه.

## مزوّد الذكاء الاصطناعي (مجاني أو مدفوع)

| | Gemini (مجاني) | Claude (مدفوع) |
|---|---|---|
| المفتاح | `GEMINI_API_KEY` من aistudio.google.com | `ANTHROPIC_API_KEY` من platform.claude.com |
| تحليل الصورة | ✅ | ✅ |
| البحث عن القيم المعلنة للمطاعم | ❌ في الخطة المجانية (يُفعَّل بـ `GEMINI_GOOGLE_SEARCH=true` في الخطة المدفوعة) | ✅ |
| وجباتك المؤكدة (الخبرة) | ✅ | ✅ |

يختار الخادم تلقائياً: Claude إذا وُجد مفتاحه، وإلا Gemini. أو حدّديه بـ `LLM_PROVIDER`.
تنبيه: بيانات الخطة المجانية في Gemini قد تُستخدم لتحسين منتجات Google.

## الحرق اليومي

- **Apple Health:** يقرأ التطبيق الطاقة النشطة والأساسية ويرسلها للخادم، مع مزامنة في الخلفية عند تسجيل تمرين جديد. ويكتب الوجبات المؤكدة في «صحتي» كـ Food correlation.
- **WHOOP:** يتم الربط بـ OAuth على الخادم عبر API v2 (`/v2/cycle`)، ويُحوَّل `kilojoule` إلى سعرات بالقسمة على 4.184. تُنسب كل دورة لليوم المحلي الذي يقع فيه منتصفها لأن دورة WHOOP تبدأ من وقت النوم.
- **أي جهاز آخر** (Garmin وFitbit وHealth Connect على أندرويد): يرسل إلى `POST /energy/samples`.
- **بدون جهاز:** يُقدَّر الحرق بمعادلة Mifflin-St Jeor مضروبة في معامل النشاط.
- **لا ازدواجية:** عند وجود أكثر من مصدر لنفس اليوم يُستخدم مصدر واحد فقط (المفضّل لدى المستخدم، أو حسب الترتيب WHOOP ثم Apple Health ثم غيرهما).
- **الهدف:** من خطة المستخدم (حرق المحافظة ± فرق الهدف)، مع إضافة جزء من الحرق الزايد في الأيام النشيطة. التفاصيل في [FEATURES.md](FEATURES.md#-الحساب-الذكي-يتعلّم-من-كل-مستخدم).

## الهيكل

```
backend/   NestJS + TypeScript — الوكيل، الوجبات، الطاقة، WHOOP، Postgres/Supabase
ios/       SwiftUI (iOS 17+) — الكاميرا، المراجعة والتعديل، لوحة اليوم، HealthKit، ربط WHOOP
```

## تشغيل الخادم

```bash
cd backend
cp .env.example .env        # ضع ANTHROPIC_API_KEY
npm install
npm test                    # 113 اختبار (Claude و WHOOP محاكيان)
npm run dev                 # http://localhost:3000
```

- **قاعدة البيانات:** إذا كان `DATABASE_URL` فارغاً تُحفظ البيانات في الذاكرة (للتطوير فقط). للإنتاج نفّذ `supabase/migrations/001_init.sql` على Supabase ثم ضع رابط الاتصال.
- **المصادقة:** في الإنتاج اجعل `AUTH_MODE=supabase` وضع `SUPABASE_JWKS_URL`. أما `AUTH_MODE=dev` فيقبل ترويسة `X-User-Id` وهو للتطوير المحلي فقط.
- **النشر:** يوجد `Dockerfile` جاهز لـ Railway. يحتاج Node 22.12 أو أحدث.
- **البحث في الويب:** يجب تفعيله لمؤسستك من Claude Console. النموذج الافتراضي `claude-sonnet-5-5`، ويمكن تغييره إلى `claude-opus-5-5` للصور الصعبة عبر `CLAUDE_MODEL`.

### الواجهات (API)

| الطريقة | المسار | الوصف |
|---|---|---|
| POST | `/meals/analyze` | multipart: `photo` والحقول الاختيارية `mealName`، `restaurant`، `portion`، `note`، `eatenAt`. يرجع مسودة وجبة |
| PATCH | `/meals/:id` | تعديل `items`، `meal_name_ar`، `restaurant`، `portionFactor` |
| POST | `/meals/:id/confirm` | تأكيد الوجبة وإضافتها لخبرة الوكيل |
| POST | `/meals` | إدخال يدوي بدون صورة |
| GET / DELETE | `/meals?date=` و `/meals/:id` | عرض وحذف |
| POST | `/energy/samples` | `{samples:[{date, source, activeKcal?, basalKcal?, totalKcal?}]}` |
| GET | `/balance?date=` | الأكل مقابل الحرق، الهدف، المتبقي، الماكروز |
| GET / PUT | `/profile` | الطول، الوزن، النشاط، الهدف، المصدر المفضل، المنطقة الزمنية |
| GET | `/integrations/whoop/connect` | رابط تفويض WHOOP |
| POST | `/integrations/whoop/sync?from=&to=` | سحب الحرق من WHOOP |

## تطبيق iOS

```bash
brew install xcodegen
cd ios && xcodegen && open StrainEat.xcodeproj
```

1. فعّل HealthKit و«Background Delivery» في Signing & Capabilities، واختر فريقك.
2. عدّل `StrainEatAPIBaseURL` في `project.yml`، أو غيّر عنوان الخادم من شاشة الإعدادات.
3. HealthKit يحتاج جهازاً حقيقياً لاختبار بيانات الحرق.

## إعداد WHOOP

1. أنشئ تطبيقاً في developer.whoop.com.
2. اجعل Redirect URI هو `https://<الخادم>/integrations/whoop/callback`.
3. الصلاحيات المطلوبة: `offline read:cycles read:workout read:profile read:body_measurement`.
4. ضع `WHOOP_CLIENT_ID` و `WHOOP_CLIENT_SECRET` و `OAUTH_STATE_SECRET` في `.env`.

> السر لا يُخزَّن في التطبيق إطلاقاً. التطبيق يفتح رابط التفويض، والخادم يستلم الرمز ويعيد المستخدم إلى `straineat://whoop`.
